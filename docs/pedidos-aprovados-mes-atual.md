## ⚠ Observação sobre o pedido 2702 (WASHINGTON LUIZ RAMOS FERRO)

Esta linha foi inserida **manualmente** com base nos dados da interface do ERP (mais fresca) porque a cadeia de sincronização estava defasada:

| Etapa | Última atualização do pedido 2702 |
|---|---|
| ERP (interface) | `Aprovado` em 2026-07-31 13:54:28 |
| View `VW_Ceres_CRM_Pedidos` (SQL Server) | `Aguardando Aprovação` (sem data) |
| ETL (sync das 17:59) | 1664 linhas re-aplicadas, mas view não refletia aprovação |
| Mirror (`mirror.crm_pedidos`) | `Aguardando Aprovação` (atualizado pelo ETL) |

**Causa raiz:** a view `VW_Ceres_CRM_Pedidos` no SQL Server (`wfrsistemas.net.br` / `CamposDealer_BI`) ainda **não havia sido reprocessada** pelo job do ERP quando o ETL rodou. O ETL/mirror estão OK — só sincronizam o que a view entrega.

**Recomendação:** abrir incidente com a equipe do ERP/SQL Server para reprocessar a view `VW_Ceres_CRM_Pedidos`. Quando a view atualizar, o ETL das 17:59 / 18:00 já estará preparado para puxar a mudança no próximo ciclo (cron `*/15 * * * *` em `/opt/etl-stack/run_etl_parallel.sh`).

No `.csv` desta pasta, a coluna `origem_sync` marca essa linha como `MANUAL_ERP` e as demais como `SYNC_OK`.

## Query SQL

```sql
SELECT
  p.emp_nome        AS filial,
  n.ngo_funil       AS funil,
  p.pdo_nropedido   AS pedido,
  n.ngo_numero      AS negocio,
  p.cli_nome        AS cliente,
  p.cli_cnpj_cpf    AS cnpj_cpf,
  p.pdo_vlrpedido   AS valor_pedido,
  p.pdo_dthaprovacao AS data_aprovacao,
  p.pdo_aprovador   AS aprovador,
  p.pdo_vendedor    AS vendedor
FROM mirror.crm_pedidos p
JOIN mirror.crm_negocios n ON n.ngo_numero = p.ngo_numero
WHERE p.pdo_situacaopedido = 'Aprovado'
  AND n.ngo_conclusao = 'Ganho'
  AND p.pdo_dthaprovacao >= date_trunc('month', CURRENT_DATE)
  AND p.pdo_dthaprovacao <  date_trunc('month', CURRENT_DATE) + INTERVAL '1 month'
  AND n.ngo_funil IN ('VENDAS','ADM','BANCOS','OFICINA','MARKETING')
ORDER BY p.pdo_dthaprovacao DESC, p.pdo_nropedido;
```
